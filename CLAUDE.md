## Non-negotiable rules (from the task — breaking them can cost the win)
1. **OSINT only.** Public, legal sources; official APIs where they exist; respect each source's terms of service and robots.txt; no logins to other people's accounts, no leaks, no scraping behind auth, no bypassing protections, no vulnerability scanning.
2. **Synthetic or anonymised test data only.** Never put a real private person into fixtures, tests, screenshots or the demo. Live connectors are shown only on synthetic personas' own pages or on public institutional examples (exchange hot wallets, DEX routers, official charity addresses).
3. **No data to unapproved external services.** All outbound HTTP goes through `EgressClient` (allowlist `config/egress-allowlist.yaml` + rate limit + cache + audit log). No telemetry/analytics SDKs. No scripts or fonts loaded from CDNs in the web app.
4. **No cloud LLM in the product.** AI is optional, **off by default**, local (Ollama) via an OpenAI-compatible API, model swappable by config. AI only assists (e.g. context classification fallback). Scoring is deterministic, rule-based and explainable.
5. **Open-source dependencies only.** Every dependency + license goes to `LICENSES.md` (generated by a script). Every label/address list in `config/labels/` starts with a header: source URL, license, retrieval date.
6. **One monorepo**, runnable with docker-compose.
7. **Secrets:** never read, print or commit `.env` or any key. Keys live only in `.env` (template: `.env.example`).

## Stack
- pnpm workspaces monorepo, TypeScript everywhere (`strict: true`).
- `apps/api`: NestJS + Prisma + PostgreSQL 16; cyclic analyses = `SchedulerService` (one `setInterval` tick, `SCHEDULER_TICK_MS`, default 30 s; the schedule and due time live in `Case.scheduleEveryMin` / `nextRunAt`) — no `@nestjs/schedule` needed.
- `apps/web`: React + Vite + Tailwind + shadcn/ui + react-i18next (`pl` default, `en`) + Cytoscape.js (graph) + TanStack Query.
- `packages/core`: pure TypeScript domain logic — address extraction/validation, classification, scoring engine, indicators, diff. **No I/O.** Fully unit-tested with Vitest.
- `fixtures/sandbox-web`: static synthetic "mini-internet" served locally on `:8088`.
- `fixtures/chain`: synthetic on-chain histories for synthetic personas.
- Optional local LLM (Ollama or any OpenAI-compatible server) is started by the user separately — there is no `ollama` service in docker-compose.yml.

## Version notes (npm `latest` is ahead of most docs)
- **Prisma is pinned to 7.10.1** (`latest` = 8 rc, which has no `prisma generate`). Config in `apps/api/prisma.config.ts`; client is generated into `apps/api/src/generated/prisma` (gitignored) by `postinstall`; PrismaClient needs the `@prisma/adapter-pg` adapter.
- **NestJS 12 is ESM-only**: `apps/api` is `"type": "module"`, relative imports need the `.js` extension.
- **TypeScript is pinned to ~6.0** (typescript-eslint does not support 7 yet).
- `@kropka/core` is ESM too (relative imports end in `.js`) and is consumed from `dist/`: api's `predev`/`prebuild`/`pretest` hooks build it, so no manual step on a fresh clone. Core does no I/O: `parseRules(yamlText)` takes the YAML as a string, the api reads the file (`RulesService`).
- Live connectors are opt-in per run (`connectors` in `POST /api/cases/:id/runs`); the default is the synthetic `sandbox` only, so a demo never queries real people. Every outbound request goes through `EgressClient` (allowlist, rate limit, cache, `AuditLog`).
- On-chain step (P3): `POST /api/cases/:id/runs` takes `chain: "fixture" | "live" | "off"` (default `fixture` = offline synthetic histories from `fixtures/chain`). `live` tries fixtures first, then mempool.space (no key), Etherscan v2 (`ETHERSCAN_API_KEY`), TronGrid (`TRONGRID_API_KEY`); a missing key is reported as a note, never an error. An ADDRESS identifier typed in by the analyst is analysed on-chain even when no page mentions it. `GET /api/chain-adapters` shows readiness.
- Valuation: stablecoins 1:1 USD; other assets only if the transfer carries a price (fixtures do; no CoinGecko yet) — otherwise "unvalued". PLN/EUR from NBP table A, last business day BEFORE the (Warsaw) transaction date, cached per process. Tests use SYNTHETIC constant NBP rates (USD 4.00, EUR 4.40) served by `test/fixture-fetch.ts`.
- Address classification order: label → bytecode (Etherscan `eth_getCode`) → exchange-deposit sweep heuristic → service-behaviour heuristic. TRON: contract check = TronGrid `POST /wallet/getcontract` (`EgressClient.post`, no cache by default, audit = host + path only); TRON exchange wallets are labelled from OKX's public Proof-of-Reserves file (`config/labels/exchanges-tron.json`, 79 large wallets of 474k) and, for Binance, from the 8 TRX addresses of Binance's public 2022 transparency post (`binance-tron.json`; partial — the current PoR file is login-gated and NOT used). The mempool.space adapter is verified against mocks only (the service was unreachable from the dev network).
- pnpm blocks install scripts by default: approved ones live in `allowBuilds` in `pnpm-workspace.yaml` (`pnpm approve-builds <pkg>`).
- Docker Hub may answer 429 on shared networks: `docker pull mirror.gcr.io/library/<image>` and `docker tag` it to the plain name.
- Web UI (P4): routes `/` (cases + demo buttons), `/new`, `/cases/:id`, `/runs/:id` (tabs: identities / links / rejected / graph / evidence; address card opens in a drawer). Demo endpoints: `POST /api/demo/case` (`{variant: "identifiers" | "address"}`), analyst decision `POST /api/links/:id/decision` (stored separately, never changes the computed score). The graph is Cytoscape `cose` layout built by `apps/web/src/lib/graph.ts`. Screenshots for the jury live in `docs/screenshots/`. Web tests are pure unit tests (format, graph, i18n key parity) — the browser walk-through is manual (Playwright).
- `NbpService` retries 5xx up to 4 times (api.nbp.pl answers sporadic 500s); if it still fails the run carries a note and the PLN values show as unvalued, never as 0.
- Product name is **KROPKA** (`APP_NAME` lives in `packages/core/src/app.ts`; the web re-exports it, the report and PDF read it). npm scope is `@kropka/*`; the compose project, DB user and DB name stay `olcys`.
- Backend messages are CODES, never sentences: `{ code, params }` (`apps/api/src/notes.ts`, `NoteError`, `noteOf`) in `summaryJson` (connectorErrors / chainNotes / chainWarnings / error) and in `GET /api/chain-adapters` (`reason`). The web translates them via `notes.<code>` (`lib/notes.ts`); the report via `NOTES_PL` in core. A test keeps core's Polish wording equal to `pl.json`.
- Report (P5): `packages/core/src/report/` builds a `ReportDoc` (pure; sections per PLAN 3.7 + decisions + limitations; every claim is FAKT / OBLICZENIE / WNIOSEK). `GET /api/runs/:id/report` = document + SHA-256 (of the canonical JSON; generation time is NOT in the hash) + evidence-set SHA-256; `/report.pdf` and `/report.json` render and store the file in `Report.content` (one row per run + format + data hash). The web page `/runs/:id/report` renders the same document. PDF = pdfmake (no browser), Roboto from pdfmake's own `fonts/` (OFL-1.1, embedded subset; arrows are replaced because Roboto has none — see `fontSafe` in `apps/api/src/report/pdf.ts`). A stored file is reused only while BOTH the data hash and the template version (`TEMPLATE_VERSION` in `report.service.ts` = hash of `pdf.ts` + `report.service.ts`) are unchanged, so editing the renderer retires old files by itself — no `DELETE FROM "Report"`.
- Request log (P5): `GET /api/audit-log?limit&problems=true`; page `/audit`. status 0 = blocked by the allowlist, −1 = network error.
- Monitoring, diff, notifications (P6): `Case.scheduleEveryMin` (15 / 60 / 1440, `PUT /api/cases/:id/schedule`) + `Case.nextRunAt`; `SchedulerService.tick()` runs due cases with the sources / chain mode of their latest run (`Run.trigger` = manual | scheduled) and books the next slot BEFORE the run. After every finished run `PipelineService.compareWithPrevious` stores a `RunDiff` (`diffRuns` in `packages/core/src/diff.ts`: new / gone addresses, score changes with the rule behind them, category changes, new transactions, thresholds crossed since, new cash-out tags, address swap on the same URL) and `Notification` rows (`notificationsFor`: new address >= 60, address swap, new threshold, new cash-out tag; `kind` + `paramsJson`, words from the web `notifications.<kind>`). `GET /api/runs/:id/diff`, `GET /api/notifications`, `POST /api/notifications/read` (`{ids}`; no ids = all unread). Section 8 of the report ("Zmiany od poprzedniego przebiegu", `report/diff-section.ts`) is always present: the first run says there is nothing to compare. A threshold that appears only because the previous run left transfers unvalued (NBP 5xx) and was crossed BEFORE that run is not "new": `diffRuns` puts it into `valuationCompleted` ("wycena uzupełniona": no notification, not in `newThresholds`).
- Address change demo: `Setting` table + `SandboxWorld` (version 1 | 2; `POST /api/demo/change {version}`, `GET /api/demo/state`). In version 2 `fixtures/sandbox-web/index.json` pages with `variants` are fetched from the variant path (same URL, other content): the persona's site shows the synthetic address A2 (`fixtures/chain/A2.json`, made by `scripts/gen-chain-fixture-a2.mjs`). Tests use `MemoryWorld` (never write shared state — test files run in parallel on one DB). Spec: `addressChange` in `fixtures/expected.json`.
- New connectors (opt-in, all through `EgressClient`; a synthetic subject is answered by the sandbox, never by the real service): `wayback` (CDX; `SourceConnector.archive()` gets the pages found so far — round 4; sandbox pages are looked up in `fixtures/sandbox-web/wayback`), `gravatar` (e-mail SHA-256; wallets only with `GRAVATAR_API_KEY`, else a `GRAVATAR_WALLETS_SKIPPED` note via `SearchInput.notify` → `summaryJson.connectorNotes`; reserved e-mail domains = sandbox), `ens` (eth_call over `ETH_RPC_URL` with `EgressClient.post`; helpers in `packages/core/src/ens.ts`; sandbox ENS fixtures answer first; a reverse record is trusted only if the name resolves back). ENS never sends the address of a synthetic persona (`fixtures/addresses.json`, `connectors/synthetic.ts`) to the RPC: only sandbox fixtures answer for it. Gotcha: the extractor reports `*.eth` names as ENS "addresses" (kind ENS, chain ETH).
- Optional local AI (`apps/api/src/ai/ai.service.ts`): `AI_ENABLED=true` + `AI_MODEL` + `AI_BASE_URL` (OpenAI-compatible, Ollama); asks only for contexts the keyword classifier left as the DISCUSSION default (`classifyContext().fallback`), max 12 per run; the answer is stored in `Evidence.metaJson.aiSuggestions` and shown as "Sugestia AI"; contexts, source types and scores come from the rules only. Unreachable model = one `AI_UNAVAILABLE` note, the run goes on. Not exercised against a real model here (mocked tests only); model choice (Bielik 4.5B / PLLuM 8B / Qwen 7B) is still open.
- Search log (pre-P7): every run stores `summaryJson.searches` (`SearchLogEntry` in core: per source × identifier in round 1, summed per source in rounds 2-4; outcome FOUND / NONE / ERROR / SKIPPED_NO_KEY / UNSUPPORTED). Connectors declare `identifiers` (+ optional `accepts`, `conditions`, `missingKey`), tag resources with `EvidenceDraft.via` and may call `SearchInput.skip(identifier, envKey)`; the pipeline builds the log from that. `GET /api/connectors` exposes `identifiers` / `conditions` / `missingKeys` (the new-case form shows which ticked sources look up each kind, warns when none does). The report has "Przeszukane źródła" in section 2 and `subjects` ("Analizowane adresy") in section 1; a subject nothing could classify has `known: false` and reads "nie ustalono".
- `telegram_public` connector: t.me/<name> (card) and t.me/s/<name> (posts with addresses); synthetic names come from `fixtures/sandbox-web/tme`; live access is OFF unless `TELEGRAM_LIVE=true` (Telegram's terms restrict access to user content; t.me/robots.txt is 404). GitHub: e-mail → `/search/commits?q=author-email:` (no token needed; reserved e-mail domains are answered by `fixtures/sandbox-web/github`, never by api.github.com).
- `EgressClient` rate limit = at most N requests in ANY rolling window of N/rate s (+50 ms): evenly spaced slots let Etherscan see 4 calls in one second ("Max calls per sec") and left the USDT contract unclassified.
- UI/report plural: i18next `_one/_few/_many/_other` for counted nouns (`pl`), `_one/_other` (`en`); the key-parity test ignores the suffixes. The report uses `plural()` from `report/pl.ts`.
