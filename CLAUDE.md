## Non-negotiable rules (from the task — breaking them can cost the win)
1. **OSINT only.** Public, legal sources; official APIs where they exist; respect each source's terms of service and robots.txt; no logins to other people's accounts, no leaks, no scraping behind auth, no bypassing protections, no vulnerability scanning.
2. **Synthetic or anonymised test data only.** Never put a real private person into fixtures, tests, screenshots or the demo. Live connectors are shown only on synthetic personas' own pages or on public institutional examples (exchange hot wallets, DEX routers, official charity addresses).
3. **No data to unapproved external services.** All outbound HTTP goes through `EgressClient` (allowlist `config/egress-allowlist.yaml` + rate limit + cache + audit log). No telemetry/analytics SDKs. No scripts or fonts loaded from CDNs in the web app.
4. **No cloud LLM in the product.** AI is optional, **off by default**, local (Ollama) via an OpenAI-compatible API, model swappable by config. AI only assists (e.g. context classification fallback). Scoring is deterministic, rule-based and explainable.
5. **Open-source dependencies only.** Every dependency + license goes to `LICENSES.md` (generated by a script). Every label/address list in `config/labels/` starts with a header: source URL, license, retrieval date.
6. **One monorepo**, runnable with docker-compose.
7. **Secrets:** never read, print or commit `.env` or any key. Keys live only in `.env` (template: `.env.example`).

## Stack
- pnpm workspaces monorepo, TypeScript everywhere (`strict: true`).
- `apps/api`: NestJS + Prisma + PostgreSQL 16; `@nestjs/schedule` for cyclic analyses.
- `apps/web`: React + Vite + Tailwind + shadcn/ui + react-i18next (`pl` default, `en`) + Cytoscape.js (graph) + TanStack Query.
- `packages/core`: pure TypeScript domain logic — address extraction/validation, classification, scoring engine, indicators, diff. **No I/O.** Fully unit-tested with Vitest.
- `fixtures/sandbox-web`: static synthetic "mini-internet" served locally on `:8088`.
- `fixtures/chain`: synthetic on-chain histories for synthetic personas.
- Optional `ollama` service (compose profile `ai`).

## Version notes (npm `latest` is ahead of most docs)
- **Prisma is pinned to 7.10.1** (`latest` = 8 rc, which has no `prisma generate`). Config in `apps/api/prisma.config.ts`; client is generated into `apps/api/src/generated/prisma` (gitignored) by `postinstall`; PrismaClient needs the `@prisma/adapter-pg` adapter.
- **NestJS 12 is ESM-only**: `apps/api` is `"type": "module"`, relative imports need the `.js` extension.
- **TypeScript is pinned to ~6.0** (typescript-eslint does not support 7 yet).
- `@kropka/core` is ESM too (relative imports end in `.js`) and is consumed from `dist/`: api's `predev`/`prebuild`/`pretest` hooks build it, so no manual step on a fresh clone. Core does no I/O: `parseRules(yamlText)` takes the YAML as a string, the api reads the file (`RulesService`).
- Live connectors are opt-in per run (`connectors` in `POST /api/cases/:id/runs`); the default is the synthetic `sandbox` only, so a demo never queries real people. Every outbound request goes through `EgressClient` (allowlist, rate limit, cache, `AuditLog`).
- On-chain step (P3): `POST /api/cases/:id/runs` takes `chain: "fixture" | "live" | "off"` (default `fixture` = offline synthetic histories from `fixtures/chain`). `live` tries fixtures first, then mempool.space (no key), Etherscan v2 (`ETHERSCAN_API_KEY`), TronGrid (`TRONGRID_API_KEY`); a missing key is reported as a note, never an error. `GET /api/chain-adapters` shows readiness.
- Valuation: stablecoins 1:1 USD; other assets only if the transfer carries a price (fixtures do; no CoinGecko yet) — otherwise "unvalued". PLN/EUR from NBP table A, last business day BEFORE the (Warsaw) transaction date, cached per process. Tests use SYNTHETIC constant NBP rates (USD 4.00, EUR 4.40) served by `test/fixture-fetch.ts`.
- Address classification order: label → bytecode (Etherscan `eth_getCode`) → exchange-deposit sweep heuristic → service-behaviour heuristic. TRON bytecode is not checked. The mempool.space adapter is verified against mocks only (the service was unreachable from the dev network).
- pnpm blocks install scripts by default: approved ones live in `allowBuilds` in `pnpm-workspace.yaml` (`pnpm approve-builds <pkg>`).
- Docker Hub may answer 429 on shared networks: `docker pull mirror.gcr.io/library/<image>` and `docker tag` it to the plain name.
- Web UI (P4): routes `/` (cases + demo buttons), `/new`, `/cases/:id`, `/runs/:id` (tabs: identities / links / rejected / graph / evidence; address card opens in a drawer). Demo endpoints: `POST /api/demo/case` (`{variant: "identifiers" | "address"}`), analyst decision `POST /api/links/:id/decision` (stored separately, never changes the computed score). The graph is Cytoscape `cose` layout built by `apps/web/src/lib/graph.ts`. Screenshots for the jury live in `docs/screenshots/`. Web tests are pure unit tests (format, graph, i18n key parity) — the browser walk-through is manual (Playwright).
- `NbpService` retries 5xx up to 4 times (api.nbp.pl answers sporadic 500s); if it still fails the run carries a note and the PLN values show as unvalued, never as 0.
- Product name is **KROPKA** (`APP_NAME` lives in `packages/core/src/app.ts`; the web re-exports it, the report and PDF read it). npm scope is `@kropka/*`; the compose project, DB user and DB name stay `olcys`.
- Backend messages are CODES, never sentences: `{ code, params }` (`apps/api/src/notes.ts`, `NoteError`, `noteOf`) in `summaryJson` (connectorErrors / chainNotes / chainWarnings / error) and in `GET /api/chain-adapters` (`reason`). The web translates them via `notes.<code>` (`lib/notes.ts`); the report via `NOTES_PL` in core. A test keeps core's Polish wording equal to `pl.json`.
- Report (P5): `packages/core/src/report/` builds a `ReportDoc` (pure; sections per PLAN 3.7 + decisions + limitations; every claim is FAKT / OBLICZENIE / WNIOSEK). `GET /api/runs/:id/report` = document + SHA-256 (of the canonical JSON; generation time is NOT in the hash) + evidence-set SHA-256; `/report.pdf` and `/report.json` render and store the file in `Report.content` (one row per run + format + data hash). The web page `/runs/:id/report` renders the same document. PDF = pdfmake (no browser), Roboto from pdfmake's own `fonts/` (OFL-1.1, embedded subset; arrows are replaced because Roboto has none — see `fontSafe` in `apps/api/src/report/pdf.ts`). A stored file is reused only while BOTH the data hash and the template version (`TEMPLATE_VERSION` in `report.service.ts` = hash of `pdf.ts` + `report.service.ts`) are unchanged, so editing the renderer retires old files by itself — no `DELETE FROM "Report"`.
- Request log (P5): `GET /api/audit-log?limit&problems=true`; page `/audit`. status 0 = blocked by the allowlist, −1 = network error.
- Do not `TRUNCATE` the dev database: the analyst may have their own cases in it. Acceptance tests clean up only what they created.
